## 1. Destructive Testing (Role: QA)

### Test Strategy
Following the "prove it's broken" methodology, tested edge cases, race conditions, and boundary scenarios.

#### ✅ Passing Tests
- [x] **Unit Tests**: All 5 tests passing successfully
  - Wizard card logic validation
  - Trump card hierarchy  
  - Lead color follow rules
  - Deck generation (60 cards)
  - Trick evaluation logic

#### ⚠️ Edge Cases Identified

##### Critical Issues
1. **Empty Deck Handling** ([game_service.dart:76-87](file:///d:/Dev/Arcana/lib/services/game_service.dart#L76-L87))
   - **Issue**: `isNotEmpty` check exists but no error handling for insufficient cards
   - **Scenario**: What happens if `round * players > 60`?
   - **Risk**: Silent failure or array out-of-bounds
   - **Recommendation**: Add explicit validation and throw meaningful exception
   ```dart
   if (cardsToDeal * _gameState.players.length > _gameState.deck.length) {
     throw GameException("Insufficient cards for round $_gameState.round");
   }
   ```

2. **Null Trump Color** ([game_service.dart:103-107](file:///d:/Dev/Arcana/lib/services/game_service.dart#L103-L107))
   - **Issue**: When ARCANUM is trump card, `trumpColor` set to `null`, waiting for dealer input
   - **Risk**: NPE if game logic proceeds before dealer chooses
   - **Recommendation**: Add state machine validation to block play until trump color selected

3. **Empty Trick Winner** ([game_service.dart:155](file:///d:/Dev/Arcana/lib/services/game_service.dart#L155))
   - **Issue**: Exception thrown for empty trick, but no upstream validation
   - **Recommendation**: Add guard clauses in calling code

##### Medium Priority Issues
4. **Dummy Card Pattern** ([ai_service.dart:230](file:///d:/Dev/Arcana/lib/services/ai_service.dart#L230))
   - **Issue**: Using magic string `"dummy"` for card ID checks
   - **Risk**: Fragile, could break if actual card has ID "dummy"
   - **Recommendation**: Use Optional/Nullable pattern or sealed class

5. **Division by Zero Risk** ([ai_service.dart:60-63](file:///d:/Dev/Arcana/lib/services/ai_service.dart#L60-L63))
   - **Issue**: `value / 13.0` assumes value is always 1-13
   - **Risk**: SHADOW (value=0) or unexpected values
   - **Current**: Handled by early return for SHADOW, but fragile
   - **Recommendation**: Add assertion or defensive check

6. **Race Condition Potential** (Player State)
   - **Scenario**: Multiple bots playing simultaneously could modify `currentPlayerIndex`
   - **Current**: Single-threaded Flutter, but risky for future async AI
   - **Recommendation**: Consider immutability or locking for game state mutations

##### Low Priority Issues
7. **Hand Sorting Performance** ([game_service.dart:90-96](file:///d:/Dev/Arcana/lib/services/game_service.dart#L90-L96))
   - **Issue**: Sorting on every deal (O(n log n) per player)
   - **Current Impact**: Negligible (max 20 cards)
   - **Future**: Could optimize with insertion sort or lazy sort on UI display

## 2. Security Audit (Role: Security)

### STRIDE Threat Model Analysis

#### ✅ Secure Elements
- [x] **No Hardcoded Secrets**: Scanned for `api_key`, `sk-`, `password` - none found
- [x] **No External API Calls**: Offline game, no network exposure
- [x] **No User Input Sanitization Issues**: No text input fields (card game)
- [x] **No SQL Injection Risk**: No database (using `shared_preferences` for local storage only)

#### ⚠️ Potential Security Concerns

##### Medium Risk
1. **High Score Tampering** ([high_score_service.dart](file:///d:/Dev/Arcana/lib/services/high_score_service.dart))
   - **Issue**: `shared_preferences` is client-side storage (easily modified)
   - **Attack Vector**: User can edit device files to inflate high scores
   - **Impact**: Integrity violation (not critical for offline game)
   - **Recommendation**: 
     - Add checksum/hash validation of high score data
     - Or accept limitation for offline-first approach
     - If adding online leaderboard: MUST use server-side validation

2. **No Access Control** (General)
   - **Current**: Single-player game with bot opponents
   - **Future Risk**: If adding multiplayer, need to implement:
     - Player authentication
     - Move validation on server
     - Prevent cheating via client manipulation

##### Low Risk  
3. **Assets Directory Traversal** ([card.dart:35](file:///d:/Dev/Arcana/lib/models/card.dart#L35))
   - **Issue**: Asset paths constructed via string interpolation
   - **Current**: Safe (controlled input)
   - **Future**: If allowing custom card packs, validate paths

## 3. Performance Analysis (Role: Performance)

### Metrics & Observations

#### Mobile Performance Considerations
> **Note**: Flutter apps require actual device/emulator testing for accurate metrics. Analysis based on code review.

##### ✅ Good Practices
- **Immutable Models**: Heavy use of final fields reduces rebuilds
- **Provider Pattern**: Efficient state management with `ChangeNotifier`
- **Asset Preloading**: Images loaded via asset path (good for caching)

##### ⚠️ Optimization Opportunities

1. **AI Decision Making** ([ai_service.dart:11-37](file:///d:/Dev/Arcana/lib/services/ai_service.dart#L11-L37))
   - **Issue**: `calculateBid()` iterates entire hand on every call
   - **Complexity**: O(n²) for probability calculation (nested loops over hand)
   - **Current Impact**: Low (max 20 cards in late game)
   - **Recommendation**: Consider memoization if AI feels sluggish

2. **Repeated List Filtering** ([ai_service.dart:96-198](file:///d:/Dev/Arcana/lib/services/ai_service.dart#L96-L198))
   - **Issue**: Multiple `.where()` chains recreate lists
   - **Example**: 
     ```dart
     validCards.where(...).toList()  // Line 136
     validCards.where(...).toList()  // Line 182
     ```
   - **Recommendation**: Cache filtered lists if used multiple times

3. **Hand Sorting on Every Deal** (See QA Section #7)
   - **Impact**: Minimal, but could defer to UI layer

4. **Google Fonts Loading** ([main.dart:31](file:///d:/Dev/Arcana/lib/main.dart#L31))
   - **Issue**: `GoogleFonts.robotoTextTheme()` may fetch fonts on first launch
   - **Recommendation**: 
     - Verify fonts are bundled (check `pubspec.yaml` for font assets)
     - Or accept first-launch download delay
